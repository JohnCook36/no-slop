# NS-001 foundation (draft)
Node.js 22+; install development dependencies with npm ci --ignore-scripts, build with npm run build, test with npm test. Run node dist/cli.js scan PATH --format json. No runtime dependencies. TypeScript Apache-2.0, @types/node and undici-types MIT (metadata/lock entries; complete license and vulnerability review pending). The lockfile pins exact versions and integrity values. Installation accesses the npm registry; scanning does not.

This is an inventory, not a semantic analyzer or security audit. Exit 0 means inventory completed according to its scope; 2 means incomplete or error; 1 reserved. Default exclusions include hidden directories/files, common generated directories, credential-like names, symlinks/junctions and non-source file extensions. UTF-8 only. Limits bound per-file bytes, total accepted bytes, entries, depth and elapsed time (cooperative, not hard interruption of filesystem calls). Complete output is sorted, but partial output may depend on directory enumeration order. Reports contain paths and size/line counts, not raw source. File names themselves could contain sensitive data; inspect before sharing.

Read-only operation is a design constraint, not a sandbox. Path checks and file identity verification reduce link traversal risk but portable Node APIs cannot atomically lock every parent path; do not scan concurrently hostile/mutating trees. On untrusted targets use an OS-isolated read-only snapshot with network disabled and no credentials. Hard links, mount boundaries, special filesystem behavior, and active races are residual risks. Do not interpret the report as proof of security.

Architecture rules, baseline, AST and TypeChecker are not implemented here; see NS-002 and architecture-analysis.md. Tests run only against synthetic fixtures, not user projects. The CI matrix must pass before this draft is ready for review.
