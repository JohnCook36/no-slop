# NS-002 semantic preview (draft)
Run node dist/cli.js analyze PATH --format json after build. The scan command still performs inventory only. Analyze exits 2 deliberately because coverage is partial; this is not a quality gate. The preview creates a local-only TypeScript Program and TypeChecker on a virtual filesystem containing only vetted source/config text. No default libraries or node_modules are read. Module paths and package entries are a restricted approximation, not full TypeScript/Node resolution. JSON/JSONC only. No code execution, plugins, scripts or emit.

Implemented: symbols and references, runtime/type-only imports/re-exports, simple nearest tsconfig aliases, local package names and simple exports, inferred module groups, iterative Kosaraju SCC and closed witness, explicit unresolved imports and selected unsupported settings. Source locations are retained, but symbol names/paths could be sensitive; do not share reports without review. No raw source or unresolved import string in reports.

Limitations: no external dependency types or standard-library types, conditional exports, project references, inherited config, configured inclusion scope, accurate JS dynamic dispatch, framework DI, flow/escape analysis, wrapper normalization, full symbol stability under renaming, or robust secret redaction. Import resolution is conservative in some cases and approximate in others; do not use this preview as evidence of absence of cycles or security flaws. Dynamic imports are included as possible runtime edges. Tests excluded by conventional names. Inferred module boundaries are not approved architecture policies. The semantic stage can consume significant memory/CPU; inventory limits do not bound the TypeChecker; run under OS resource limits on untrusted inputs. Future stage must close these gaps, measure accuracy, and add actual architecture rules. CI and manual review required before merge.
